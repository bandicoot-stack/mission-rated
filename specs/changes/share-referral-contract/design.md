# Design: Trustworthy Share + Referral Contract

## Approach

Use first-party URL parameters and existing Mission Rated analytics infrastructure. Keep attribution deliberately coarse and non-identifying.

### Referral URL

Recommended shape:

`https://www.missionratedhq.com/<deal-path>?ref=share&campaign=<bounded-value>`

Implementation may use the existing canonical deal URL shape. `ref` and `campaign` values must be allowlisted or bounded/sanitized before analytics storage.

### Event payload

Share/referral events should contain only fields needed for growth measurement, such as:

- event name;
- canonical page/deal identifier;
- referral source (`share`, `qr`, `weekend_brief`, etc. when supported);
- bounded campaign identifier;
- landing path;
- timestamp handled by the authoritative analytics layer.

Do not include email, name, auth token, raw query string, or arbitrary external URL data.

## Separation of evidence

Analytics events describe behavior. The savings ledger describes documented economic value. They are separate systems/contracts even if reported in one scorecard.

A browser event is not sufficient evidence for `confirmed_redemption` or `documented_savings` unless a later approved implementation explicitly establishes an authoritative server-side contract.

## Failure behavior

- If native share fails or is unavailable, allow copy-link fallback.
- If analytics submission fails, sharing should still work; user utility is primary.
- If referral parsing fails, render the canonical deal normally and omit attribution.
- Never block deal access because attribution is unavailable.

## Security / privacy

- Accept only same-origin Mission Rated share destinations generated by application code.
- Sanitize/bound attribution values server-side before persistence.
- Never trust client-provided savings amounts.
- Never treat referral identifiers as authorization or identity.

## QA

Verify:

1. Native-share-capable mobile path.
2. Copy-link fallback path.
3. Referral landing with valid attribution.
4. Landing with malformed/oversized attribution.
5. Deal page with no attribution.
6. Analytics failure does not break sharing.
7. No share/referral/outbound event changes the documented savings total.
